# /wpw:brd <需求名>

接收客户需求，生成 BRD（业务需求文档）。这是六阶段流程的入口。
**hybrid 输入**：有客户需求描述则结构化整理，无则交互问答。

> **联动 Skill**：`@brainstorming`（需求模糊时辅助澄清，可选）· `@humanizer-zh`（落盘后去机器腔）

## 角色定位（重要）

BRD 面向**业务方**（通常非技术背景）。AI 在本阶段：

- **聚焦业务**：理解"做什么 / 为什么 / 值不值"，用业务语言沟通
- **判断完整性**：评估需求是否完整清晰；不完整则用 AskUserQuestion 澄清——但**只问业务问题**（目标、范围、优先级、约束），不问技术实现
- **不主动谈技术文件**：除非用户主动问及技术实现，否则**不**讨论具体技术文件/模块/框架（如"修改 src/auth.ts""用 Redis"）。技术方案留给 Explore / Design
- **独立估算成本**：AI 自行分析实现该需求的技术成本，按业务可理解的步骤拆分，估算每步所需**人力（人）与时间（人日）**，填入"成本评估"表。这是给业务方决策用的，**不要问用户**——用户非技术背景，答不了；AI 凭自身分析给出

## 执行流程

### 阶段一：CLI 准备

```bash
wpw new <需求名>                    # 幂等创建需求
wpw check brd -c <需求名> --json    # 依赖检查（BRD 无前置，必通过）
wpw template brd -c <需求名>        # 取 BRD 模板路径
```

读取返回的模板路径文件，按其结构填充。

### 阶段二：AI 生成（hybrid 输入）

- **若用户提供了客户需求描述**（口述/邮件/会议纪要）：结构化整理为 BRD 大纲
- **若无输入**：用 **AskUserQuestion** 逐项询问**业务**问题：
  - 业务背景（当前痛点）
  - 业务目标（可量化）
  - 用户故事（作为...我希望...以便...）
  - 成功指标
  - 约束与假设

**完整性判断**：若关键业务信息缺失（目标不清/范围模糊/无成功指标），追加澄清问题；信息齐全后进入下一步。**澄清只问业务，不问技术。**

### 阶段三：AI 成本估算（独立分析，不问用户）

AI 基于需求自行拆解实现步骤（业务可理解的粒度，如"登录""下单""支付对接"，而非"搭 JWT 中间件"），估算每步人力与时间，填入"成本评估"表。

- **不向用户征询技术细节**——用户非技术背景；AI 凭自身分析给出
- 表末附"粗略估算，最终以 Design / Plan 为准"声明

### 阶段四：确认大纲

输出 BRD 大纲（含成本评估表），等用户确认。**🛑 禁止静默落盘**。
若用户对成本有疑问，可解释估算依据（仍用业务语言，不展开技术文件）。

### 阶段五：落盘 + CLI 收尾

确认后写入 `wpw/active/<需求名>/BRD-<需求名>.md`，然后：

```bash
wpw done brd -c <需求名>
```

### 阶段六：AI 后处理

执行 `after_brd` hook，用 `@humanizer-zh` 去机器腔。

输出「已落盘 → [文件路径]」，提示下一步可执行 `/wpw:prd <需求名>`。
