# /wpw:sync <需求名>

代码改动后同步更新相关文档。**禁止大面积覆写**。

## 执行流程

### 1. 先改代码

精准修改受影响源文件，遵守靶向替换红线（只改必要部分）。

### 2. 扫描受影响文档

检查 `wpw/active/<需求名>/` 下与本次变更相关的 BRD / PRD / Design / Plan / Test。

**知识图谱关联查询**（推荐，定位更准不漏同步）：

```bash
wpw graph update   # 增量更新图谱
```

- 图谱不存在 -> 强提示「⚠️ 未构建知识图谱，建议先执行 `wpw graph build` 以精准定位受影响文档」，但仍可回退人工关联继续

用业务映射边反向找改动代码关联的需求文档：

```bash
# 查改动文件的上游，沿 business_map 边找到关联的需求节点
wpw graph query --upstream <改动文件节点ID> --depth 3 --json
```

- 命中的 L1 需求节点即对应需同步的文档目录
- 查询无结果 -> 回退人工关联，提示「图谱未匹配到相关节点」

### 3. 同步更新文档

只改相关段落，在变更处追加：

```
> 变更记录：[日期] [变更摘要]
```

使用 `[~]` 标记废弃节点，尾部追加补丁记录。**禁止大面积覆写**。

### 4. 自检

用 `@humanizer-zh` 去机器腔。
