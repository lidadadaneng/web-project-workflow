## Purpose

从 PRD 文档中结构化提取需求功能条目（功能编号、名称、优先级、描述等），作为 L1 需求节点的属性存储，提升需求节点的信息密度与语义检索效果，为后续更细粒度的需求追踪打基础。

## ADDED Requirements

### Requirement: PRD 功能清单结构化提取
需求解析器 SHALL 从 PRD 文档的「功能清单」表格中结构化提取功能条目，包括编号、功能名称、优先级和描述信息。提取结果 SHALL 作为 L1 需求节点的 `features` 属性存储。

#### Scenario: 从标准功能清单表格提取
- **WHEN** 解析 PRD 文档，且文档包含「功能清单」章节与标准 Markdown 表格（列：编号 / 功能 / 优先级 / 描述）
- **THEN** 系统提取每一行的功能条目
- **AND** 每个条目包含 id（编号，如 F1）、name（功能名）、priority（优先级，如 P0）、description（描述）
- **AND** 条目数组按编号顺序排列
- **AND** 存储到需求节点的 `attrs.features` 属性中

#### Scenario: 功能清单表格列顺序不敏感
- **WHEN** PRD 中功能清单表格的列顺序与标准模板不一致
- **THEN** 系统通过表头名称识别列（编号、功能、优先级、描述）
- **AND** 不依赖固定的列索引

#### Scenario: 无功能清单时降级
- **WHEN** PRD 文档中没有「功能清单」章节或表格
- **THEN** `features` 属性为空数组
- **AND** 不报错，需求节点正常生成

### Requirement: 详细功能说明文本提取
需求解析器 SHALL 从 PRD 的「详细功能说明」章节中提取每个功能条目的详细描述，用于富化功能条目的信息，提升语义检索质量。

#### Scenario: 匹配功能编号提取详细说明
- **WHEN** PRD 文档中存在「详细功能说明」章节，且包含 `### F1: <功能名>` 格式的子章节
- **THEN** 系统提取每个子章节的内容，补充到对应功能条目的 `description` 字段
- **AND** 通过功能编号（如 F1）与功能清单中的条目关联

#### Scenario: 详细功能说明中包含验收标准
- **WHEN** 详细功能说明中包含「验收标准」列表项
- **THEN** 系统提取验收标准文本，合并到功能条目的 `description` 中
- **AND** 保留验收标准的关键信息（去重 markdown 标记后）

### Requirement: 功能条目参与向量化
功能条目信息 SHALL 参与 L1 需求节点的向量化文本构建，以提升需求检索的细粒度匹配能力。

#### Scenario: 功能描述加入向量文本
- **WHEN** 生成 L1 需求节点的 embedding 向量时
- **THEN** 向量化文本包含所有功能条目的名称和描述
- **AND** 每条目的格式为「<编号> <名称>：<描述>」
- **AND** 追加在原有的 BRD+PRD 纯文本之后

#### Scenario: 无功能条目时向量文本不变
- **WHEN** 需求没有功能条目（features 为空）
- **THEN** 向量化文本与之前保持一致（仅 BRD+PRD 纯文本）
- **AND** 向量结果不受影响
