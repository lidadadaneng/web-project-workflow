大语言模型已从代码补全发展为参与需求分析、编码与测试的开发智能体。受上下文窗口限制，智能体需要反复检索项目文件并组织输入；长对话中的上下文淘汰又使已有知识难以持续复用，增加了时间和 Token 开销。

本文提出一种面向 AI 辅助软件开发的图谱驱动上下文工程方法。该方法解析项目源码，建立模块、文件和代码元素之间的结构依赖索引；将功能需求组织为能力知识单元，通过业务与代码的映射关系形成知识图谱，并以本地文件保存。执行开发任务时，先通过语义匹配定位能力节点，再沿图关系提取任务相关子图，生成预算约束下的上下文。需求迭代后同步更新能力单元、代码索引及映射关系，使项目知识能够持续维护和复用。

基于上述方法，设计并实现 WPW（Web Project Workflow）系统，通过功能测试核对实现行为。以美食推荐系统为实验载体，在相同前置版本上比较 WPW 与 OpenSpec 完成基础搭建、业务核心、迭代增强和连续需求四类任务时的完成情况、Token 消耗与耗时；在同一代码快照上比较非图谱检索、图谱增强检索和完整 WPW 的必要文件覆盖与上下文开销。任务级比较同时涉及流程与知识供给差异，代码定位实验进一步考察上下文获取环节。在当前项目和实验范围内，WPW 的任务整体 Token 消耗更低，启用图谱上下文后的代码定位开销也有所减少，表明该方法能够降低上下文管理的额外开销。

关键词：大语言模型；上下文工程；AI 辅助软件开发；代码知识图谱

## ABSTRACT

Large language models have evolved from code completion tools into agents that participate in requirements analysis, implementation, and testing. Limited context windows require these agents to retrieve project files and organize inputs repeatedly. As long conversations displace earlier context, previously acquired knowledge may need to be retrieved again, increasing execution time and token consumption.

This thesis proposes a graph-driven context engineering method for AI-assisted software development. The method parses project source code to index structural dependencies among modules, files, and code elements. Functional requirements are organized into capability knowledge units and linked to code through explicit mappings, forming a knowledge graph stored in local files. For each task, semantic matching first identifies relevant capability nodes. Graph traversal then extracts a task-related subgraph and generates context within a token budget. Capability units, code indexes, and mappings are updated as requirements evolve, supporting continued maintenance and reuse of project knowledge.

The method is implemented in WPW (Web Project Workflow), whose behavior is checked through functional testing. A food recommendation system serves as the experimental subject. Starting from the same project versions, WPW and OpenSpec complete four types of development tasks: basic setup, core business functionality, iterative enhancement, and continuous requirements. The comparison examines task completion, total model tokens, and execution time. A separate code-location experiment uses the same code snapshot to compare non-graph retrieval, graph-enhanced retrieval, and full WPW in required-file coverage and context acquisition cost. Because task-level comparisons also involve differences in workflow and knowledge supply, the code-location experiment examines context acquisition more directly. Within the project and experimental conditions studied, WPW uses fewer tokens overall for development tasks, while enabling graph context reduces the cost of locating required code. These results indicate that the proposed method can reduce the additional overhead of context management; they do not establish that all task-level differences arise from retrieval alone.

Key Words: Large Language Models; Context Engineering; AI-Assisted Software Development; Code Knowledge Graph
