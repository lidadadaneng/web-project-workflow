# 论文 AIGC 降重

## 目标与优先级

按以下顺序判断改写是否合格：

1. **语义等价**：研究对象、问题定义、方法机制、实验设计、数据和结论均不得改变。
2. **学术有效**：论证关系清楚，术语准确，不虚构数据，不把提纲或计划稿伪装成实验结果。
3. **表达自然**：减少模板句、机械排比、均匀句长和抽象名词堆叠。
4. **检测值下降**：仅在前三项合格后使用检测结果评价改写效果。

低分不是充分条件。凡是通过删除核心信息、弱化或强化结论、改换研究边界取得的低分版本，一律判定失败。

## 适用范围

适用于：

- 学位论文摘要、引言、相关技术、方法、系统实现、实验分析和章末小结；
- Word/PDF AIGC 检测报告的风险分析；
- 在不改变原意的前提下进行逐段降重；
- 比较多轮检测结果并沉淀有效改写规则。

不适用于：

- 传统重复率、引文规范或抄袭来源核查；
- 尚无实验数据时编造结果；
- 为追求检测值而口语化、故意加入病句或随机替换术语。

## 输入要求

开始前确认以下材料：

- 待改写原文，原文是唯一语义基线；
- 原文在论文中的功能，如摘要、研究现状、方法或实验结果；
- 已有检测报告及检测平台；
- 必须保留的正式术语、数字、机制名称、实验组数和结论强度；
- 是否只输出候选文本，还是经确认后同步论文源文件。

缺少实验数据时，保留原文已有表述的强度，不擅自补充数值。若原文结论与正文证据冲突，应先指出冲突，由作者决定，不可暗中改写研究结论。

## 标准流程

### 1. 建立同平台基线

检测对比必须尽量使用同一平台、同一输入范围和同一排版方式。不同平台的数值不能直接比较。

测试时只提交目标正文，不要混入：

- “摘要”等标题；
- 关键词；
- Markdown 标记；
- 改写说明、检测建议或聊天内容；
- 与目标文本无关的前后段落。

若报告把全文合并为一个片段，只能得到整体分数，不能据此断言某个句子风险最高。需要定位时，将自然段分别送检。

### 2. 建立语义台账

改写前把原文拆成不可丢失的原子信息。至少检查以下类别：

| 类别 | 核对内容 |
|---|---|
| 背景 | 技术变化、研究场景和适用范围 |
| 问题 | 问题数量、具体表现及因果关系 |
| 方法 | 方法总称、组成部分和处理对象 |
| 机制 | 正式名称、输入、处理过程、输出和作用 |
| 实现 | 系统或工具名称及其与方法的关系 |
| 实验 | 实验载体、方案数量、消融设置和评价维度 |
| 结果 | 结果方向、比较对象、结论强度和限制条件 |
| 术语 | 中英文术语、缩写、数字和专有名称 |

摘要改写还必须逐项保留“背景 -> 问题 -> 方法 -> 实现 -> 实验 -> 结果”信息链。可以改变句序和段落节奏，但不能改变逻辑依赖。

### 3. 识别高风险表达

优先处理经过本项目检测验证的高风险特征：

- “随着……然而……针对上述问题……首先……其次……再次……在此基础上……结果表明……”完整模板；
- 每段严格采用“总述 + 三项列举 + 空泛收束”；
- 连续使用“本文提出、本文构建、本文设计、本文实现”；
- 多个句子长度接近，均为“主体 + 通过某方法 + 实现某目标”；
- 同一组问题、机制和贡献在不同位置仅作近义复述；
- 抽象名词密集，但缺少明确的处理对象、动作和边界；
- 实验章节仍使用“比较、观察、待回填、若结果不符”等计划稿口吻。

AIGC 检测只能提供风险信号，不能证明文本由 AI 生成。不要把规范术语、引用或必要的学术结构本身视为错误。

### 4. 等义重写

采用以下变换，逐项对应语义台账：

1. 从原文已有事实切入，不另造案例、背景或实现细节。
2. 把“首先、其次、再次”改成问题与方法之间的因果推进，但保留每项机制。
3. 拆开过长的并列句，并将过短、功能相同的句子合并，使句长自然变化。
4. 为句子补足明确主语和动作，减少“进行、实现、有效、系统性”等空泛谓语。
5. 保留正式术语，允许改变术语周围的句法，不做随机同义词替换。
6. 将重复出现的贡献概括压缩为一次完整说明；章节职责要求重复时，改变叙述功能，而非只换词。
7. 结尾回到原文已有结果或研究边界，不添加拔高式结论。

允许改变：

- 句子长短；
- 主动句与被动句；
- 信息在相邻句之间的分配；
- 并列关系的表达方式；
- 不影响逻辑的段落划分。

禁止改变：

- 研究对象和适用范围；
- 问题、机制、实验方案或评价维度的数量；
- 方法与实现载体之间的关系；
- 因果关系、比较对象和结论方向；
- 已有数字、参数、术语及引用含义；
- 原文的谨慎程度或结论强度。

### 5. 语义回归检查

候选稿完成后，按语义台账逐项回查：

- 原文每项信息在候选稿中都有明确对应；
- 候选稿没有出现原文不存在的新事实；
- 正式机制没有被泛化成普通功能描述；
- 方法贡献没有被替换为更具体但未经原文确认的实现细节；
- 实验载体、对比方案、消融组和评价指标保持一致；
- 结果没有被删除、弱化、强化或改写成计划；
- 术语、数字、时间、主客体和否定关系均一致。

任一项不通过，先修复语义，再检测 AIGC。不得用检测低分为语义漂移辩护。

### 6. 检测与迭代

每轮只保留一个主要候选稿，并记录：

| 字段 | 内容 |
|---|---|
| 平台 | 检测工具及版本或日期 |
| 输入范围 | 正文、字符数、是否含标题/关键词 |
| AIGC 值 | 报告原值 |
| 语义检查 | 通过/失败及原因 |
| 修改策略 | 本轮采用的主要结构调整 |
| 结论 | 接受、继续修改或放弃 |

若整体值仍高，先分段检测并处理最高风险段，不要对已经自然的段落反复换词。连续三轮没有改善时，停止盲改，重新检查输入污染、平台波动、文本功能和语义约束。

## 摘要专项检查

摘要是高风险区域，交付前确认：

- 开头交代原有技术背景，没有另造研究动机；
- 原文列出的所有核心问题仍然存在；
- 方法总称和每项核心机制均保留；
- 实现工具仍是方法的载体，未被写成研究对象本身；
- 实验载体、方案数、消融组数和评价维度没有变化；
- 结果方向与原摘要一致；
- 不用“首先、其次、再次”串联全部贡献；
- 不为了自然化而把学术摘要改成经验叙事或产品介绍。

## 本项目已验证案例

同一摘要在朱雀 AI 检测助手上的三轮结果：

| 版本 | AIGC 值 | 语义评价 | 结论 |
|---|---:|---|---|
| 第一轮 | 0.6070 | 基本保留研究内容，但结构仍过于规整；输入还混入关键词和改写说明 | 继续修改 |
| 第二轮 | 0.1415 | 场景化切入和句式打散有效，但删弱总体框架并替换部分正式贡献，发生语义漂移 | 低分但失败 |
| 第三轮 | 0.0124 | 保留问题定义、三项机制、wpw 实现、实验设计、评价维度和结论，仅重组句法与信息顺序 | 接受 |

由此得到的项目经验：

- 有效做法是打散模板结构、改变句长、把机械列举改成因果推进；
- 无效做法是只替换近义词，或继续维持完全对称的“问题—方法—实验”句式；
- 不可接受的做法是删除结果、弱化正式机制或增添原文没有的具体实现；
- 检测值必须与语义检查共同记录，不能单独作为验收标准；
- 0.0124 是特定平台、特定文本和特定时间的结果，不保证其他章节或平台得到相同数值。

## 项目文件更新规则

本项目的 Markdown 章节是唯一正文源。需要正式应用改写时：

1. 先输出候选稿和语义核对结果，等待作者确认；
2. 作者明确要求落盘后，修改对应的 `论文/*.md` 源文件；
3. 不直接修改 docx 正文；
4. 按 `论文/论文写作SKILL.md` 的流程同步 docx 与 LaTeX；
5. 更新后复查术语、引用、图表编号和上下文衔接。

若用户只要求生成候选文本或进行检测分析，不修改任何论文文件。

## 输出格式

默认先给可直接检测的纯正文，不附带标题、关键词、Markdown 标记或解释。用户要求解释时，再单独提供：

- 本轮处理的高风险结构；
- 语义台账核对结果；
- 与上一版的差异；
- 下一轮检测应使用的输入范围。
