## ABSTRACT

- 研究背景：LLM 辅助开发已拓展至多个软件工程活动，但复杂项目开发面临上下文不足、知识割裂与流程不可控挑战。
- 研究内容（三个创新点）：① 面向 AI 辅助开发的软件工程上下文工程框架（需求->设计->计划->测试->实现全过程上下文管理）；② 面向软件项目知识持续利用的双层知识组织模型（能力知识层 + 代码结构层统一关联）；③ 图谱驱动的任务级上下文生成方法（检索->子图裁剪->骨架抽取->压缩生成）。
- 系统实现：实现 wpw 工具作为方法载体（CLI 层 TypeScript + AI 层 Claude Code Skill，14 个 /wpw 命令 + 文件系统层；多语言源码解析、本地 Embedding、零数据库）；以基于大模型的美食推荐系统为实验载体。
- 实验验证：受控对比 4 种大模型辅助开发方式 + 三组消融（知识组织/上下文生成/流程约束）+ 组件级基线，回答 RQ1-RQ4；不评价推荐算法准确率。
- 关键词（英）：AI-Assisted Software Development；Context Engineering；Agent Workflow；Code Knowledge Graph；Context Compression；Large Language Model；Recommendation System

## 盲审/答辩防御要点（写作时内化到对应章节，不单独成节）

1. **"你的方法为什么比 GPT/Claude 强？"** -> 本文不改变基础模型能力，而是优化模型执行软件工程任务时获得的信息组织方式；研究对象是模型输入上下文质量，而非模型本身（1.1 定位句 + 5.1.1）。
2. **"为什么不直接使用长上下文？"** -> 长上下文解决的是容量问题，本文关注相关上下文的选择问题；项目规模增长下全量输入仍存在成本高、噪声大、知识关联弱的问题（1.1.2 + 5.4.3）。
3. **"为什么不和所有开源工具比较？"** -> OpenSpec / Superpowers 分别覆盖规格驱动与 Agent 流程驱动的代表性方向；研究目的是分析不同上下文管理机制的影响，非工具排行榜（5.1.3）。
