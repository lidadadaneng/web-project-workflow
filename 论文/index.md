# 基于大模型的美食推荐系统设计与实现--面向 AI 辅助开发的上下文工程方法研究

> 本文件为论文**结构大纲与状态看板**。正文写入独立章节文件；详细写作素材存档于 `index.填充版备份.md`。
>
> 核心思想（2026-08-16 定稿）：**研究 AI Agent 在长期软件开发过程中的上下文构建、管理与复用方法**。三层定位：研究对象 = 面向 AI 编程智能体的软件工程上下文组织方法（能力-代码双层知识模型 / 任务上下文生成 / Spec 增量演化）；实现载体 = wpw 系统（方法实现，非 CLI 工具）；实验载体 = 基于大模型的美食推荐系统（常规推荐系统，不含大模型增强推荐）。
>
> 逻辑主线：AI Agent 发展 -> 长期项目上下文成为瓶颈 -> 已有模型/Agent/Spec/Context 研究各有空白 -> 提出上下文工程方法（C-L1-L2-L3 双层模型 + 增量演化 + 任务上下文生成）-> wpw 实现 -> 美食推荐系统验证（含 T4 多轮演化实验）。
>
> 三条红线：不评价推荐算法创新、不挑战基础模型能力（也不替代 Agent Harness）、不做工具排行榜。

## ABSTRACT

- 研究背景：大模型推动 AI Agent 参与软件开发，但长期项目开发面临上下文瓶颈：代码库规模增长超出窗口有效范围、业务知识与代码结构割裂、项目演化缺少持续知识积累机制。
- 研究内容（四个创新点）：① 面向长期软件演化的能力-代码双层知识组织模型（Spec -> Capability -> Code，C-L1-L2-L3）；② 图谱驱动的任务上下文生成方法（面向 Agent 的任务级子图生成，最小充分上下文）；③ Spec 增量知识演化机制（工程化知识积累）；④ wpw 系统实现与基于大模型的美食推荐系统验证（含多轮需求演化实验）。
- 系统实现：wpw 系统（CLI 层 TypeScript + AI 层 Claude Code Skill，14 个 /wpw 命令 + 文件系统层；多语言源码解析、本地 Embedding、零数据库、图谱增量更新）。
- 实验验证：受控对比 4 种上下文管理范式 + 三组消融 + T4 多轮需求演化实验，回答 RQ1-RQ3；不评价推荐算法准确率。
- 关键词（英）：AI-Assisted Software Development；Context Engineering；Code Knowledge Graph；Context Compression；Large Language Model；Recommendation System

## 盲审/答辩防御要点（写作时内化到对应章节，不单独成节）

1. **"为什么比 GPT/Claude/DeepSeek 强？"** -> 本文不改变基础模型能力，研究对象是模型输入上下文的质量与组织方式（1.1.1 研究边界声明）。
2. **"为什么不用 Agent 运行框架（Harness）？"** -> 本文不替代 Harness，在智能体已具备执行能力之后研究软件工程项目的高质量上下文构造（1.1.1 研究边界声明）。
3. **"为什么不直接使用长上下文？"** -> 长上下文解决容量问题，本文关注相关上下文的选择问题（1.1.1 问题（1）+ 5.4.3）。
4. **"为什么不和所有工具比较？"** -> OpenSpec/Superpowers 覆盖规格驱动与 Agent 流程代表性方向；研究目的是分析上下文管理机制的影响，非工具排行榜（5.1.3）。
