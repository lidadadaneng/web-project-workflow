%% 中文摘要页
\begin{ChineseAbstract}
随着大模型在需求分析、代码生成与软件测试等软件开发环节的广泛应用，软件开发智能体需从项目中检索相关文件、解析代码语义，并将信息整合为任务上下文。然而，受大模型上下文窗口长度的制约，历史检索结果易在长对话过程中被挤出有效范围。若业务需求与代码实现的映射关系仅留存于单次对话会话中，该关联知识也无法被后续开发任务复用。这两点共同导致智能体需重复执行检索与上下文组织流程，造成不必要的时间成本与 Token 消耗。

针对上述问题，本文提出一种面向人工智能（Artificial Intelligence，AI）辅助软件开发的知识图谱驱动上下文工程方法。该方法首先通过静态解析项目源码，构建模块、文件与代码元素间的结构依赖索引。其次采用能力规范对项目业务功能进行形式化描述，通过业务—代码映射关系将二者融合为知识图谱，并以本地文件形式持久化存储。接收到开发任务时，方法通过语义匹配定位图谱中相关能力节点，再沿图结构关系抽取任务相关子图，经裁剪与压缩处理后生成满足 Token 预算约束的任务上下文。同时，为保障图谱在项目迭代中的可用性，方法支持在需求变更或代码迭代后增量更新能力规范、代码索引及映射关系。

基于上述方法，本文设计并实现了一套 Web 项目开发工作流（Web Project Workflow，WPW）原型系统。系统采用智能体交互层、命令行执行层与文件存储层的三层架构，实现开发流程管控、知识图谱构建、任务上下文生成与知识增量维护四大核心功能，并通过可视化控制台展示流程状态与图谱结构信息。最后，以美食推荐系统为案例开展验证实验，结果表明，系统各模块功能均符合设计预期。在同等实验设置下，与对比方法 OpenSpec 相比，WPW 完成开发任务的模型总 Token 消耗更低。

\ChineseKeywords{大语言模型；上下文工程；AI 辅助软件开发；代码知识图谱}
\end{ChineseAbstract}

%% 英文摘要页
\begin{EnglishAbstract}
As large language models are widely applied to requirements analysis, code generation, and software testing, development agents retrieve project files, interpret code semantics, and assemble task context. However, limited context windows can displace earlier retrieval results during long conversations. If business-to-code mappings remain confined to one session, subsequent tasks cannot reuse them. Together, these limitations require repeated retrieval and context organization, incurring unnecessary time and token costs.

To address these problems, this thesis proposes a knowledge-graph-driven context engineering method for AI-assisted software development. First, static source analysis indexes structural dependencies among modules, files, and code elements. Capability specifications then formally describe business functionality and connect it to code through mappings, forming a knowledge graph persisted in local files. When a task arrives, semantic matching locates relevant capability nodes. Graph traversal extracts a task-related subgraph, which is pruned and compressed into context within a token budget. To maintain usability during project evolution, capability specifications, code indexes, and mappings are updated incrementally after requirement or code changes.

Based on this method, WPW (Web Project Workflow) is designed and implemented as a prototype. Its three layers handle agent interaction, command-line execution, and file storage, supporting workflow control, knowledge graph construction, task context generation, and incremental knowledge maintenance. A visual console displays workflow status and graph structure. Finally, validation uses a food recommendation system as a case study. Results show that module behavior meets design expectations and that, under identical experimental settings, WPW uses fewer total model tokens than OpenSpec for development tasks.

\EnglishKeywords{Large Language Models; Context Engineering; AI-Assisted Software Development; Code Knowledge Graph}
\end{EnglishAbstract}
