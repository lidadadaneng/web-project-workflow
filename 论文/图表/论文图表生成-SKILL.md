# 论文图表生成 Skill

## 适用范围

本规则用于本论文及后续论文图表的设计、生成、插入和验收。默认产出包括：

- 可编辑的 Visio 源文件（`.vsdx`）；
- 与论文编排兼容的 PNG 预览图；
- Markdown、LaTeX 或 DOCX 中的正式插图及图注；
- 本目录下可复现的生成脚本。

## 标准 SOP

### 1. 读取上下文

先读取目标章节、图表清单、相邻图表说明和论文模板。明确该图回答的唯一问题、输入输出关系、层级关系和需要保留的专业术语。总图只表达总体结构，局部算法、字段定义和详细流程留给后续图表。

### 2. 确定图意和版式

- 论文总体架构优先采用分层架构图、流程闭环图或数据流图。
- 先画外部层级边界，再放层标题、模块和箭头。
- 同一层的元素应组成一个视觉组，整体水平居中。
- 层标题与虚线框顶部保持统一间距，建议以同一基线或同一相对偏移量放置。
- 说明文字不得贴边、压线或落在模块框上；说明文字与块元素之间保留明确空隙。
- 所有边界、模块和箭头应保留足够的安全边距，避免第一块元素与外框形成重合双线。

### 2.1 强制版式门槛

- 先按最终论文中的插图宽度（通常为 `0.95\textwidth`）判断可读性，再决定画布比例；不得为保留空白而使用过高或过宽的画布。
- 核心模块、层级边界和关键路径组成的有效内容区，宽度应占页面的 70% 以上、高度应占页面的 60% 以上；仅在确有多个独立视觉组时例外。安全边距不是大面积留白的理由。
- 文字大小以最终插图中的相对比例验收，不以 Visio 的 pt 值或导出像素值作为标准。定义文字行高比 `r_h = 单行文字可见高度 / PNG 总高度`：核心模块和主流程方块 `r_h >= 3.5%`，普通方块和判定菱形 `r_h >= 3.0%`，层级标签 `r_h >= 2.4%`，辅助说明 `r_h >= 2.0%`。脚本中的 pt 仅是绘图实现参数，不能替代最终比例验收。
- 方块内文字允许换行，但单个方块最多 3 行；每一行都必须达到对应类别的文字行高比，超过 3 行必须缩短标签、拆分节点或改用图外图注。最终 PNG 在论文实际插图比例下应能直接辨读。
- 不得只通过裁去外边距修复版面。调整有效内容比例时，必须同时检查并协调画布比例、节点尺寸、字号、层间距和箭头长度。
- 图例应放在独立留白区，不得与模块、连线或虚线边界争夺空间；无必要时不增加图内说明句。
- 模块框内文字必须保留可见内边距：上下至少为一行文字高度的 0.35 倍，左右至少为一个汉字宽度；中英文混排或两行标签不得贴近边框。
- 文字禁令（硬性不通过条件）：任何文字不得超出所属元素框、压线或覆盖边界；元素框内文字最多 3 行，必须在导出 PNG 的 100% 检查中完整可见。文字放不下时只能扩大元素、缩短标签或拆分元素，不得缩小到不可读或让文字溢出。
- 流程箭头必须从一个明确节点的边缘连接到另一个明确节点的边缘；不得出现悬空箭头、穿过节点的箭头或无法判断终点的长回环线。回退路径应拆成“降级/重试节点 + 返回目标节点”两段或多段可追踪连接。
- 关系连线不得彼此交叉；同一层或同一分支优先使用同向水平/垂直直线，并通过对齐节点、分上下泳道或设置独立连线走廊消除交叉。确需跨层连接时使用正交折线，折点应位于节点外的留白区，禁止以一条斜线穿越其他节点或连线。
- 关系连线禁令：不得使用斜向实线表达跨列关系，不得让实线与实线、实线与虚线相交，不得让一条连线穿过任何模块框。优先将节点按列对齐，使用水平/垂直直线；无法无交叉表达时应删减非核心关系或拆分图，而不是保留交叉线。
- 虚线仅用于分区边界、泳道或图例，不得用虚线表示模块间关系、规则来源或方向；所有需要表达方向的关系必须使用端点清晰的实线箭头，并保证箭头落在目标模块边缘。

### 2.2 图形类型选择

作图前先用一句话写出该图要回答的问题，再按信息关系选图形；不能因为已有脚本容易复用就套用错误版式。

| 信息关系或问题 | 首选图形 | 必须表达的要素 | 不应使用 |
|---|---|---|---|
| 系统由哪些层、模块和接口构成 | 分层架构图 / 组件关系图 | 层级边界、组成关系、跨层接口 | 逐步流程图 |
| 概念或实体之间如何关联 | 本体图 / 关系图 | 节点类型、关系方向、关系标签 | 将关系硬排成时间顺序 |
| 输入经过哪些连续步骤产生输出 | 标准流程图 | 起点、处理步骤、箭头方向、终点 | 仅并列模块的关系示意图 |
| 过程含有并行分支、汇聚或阈值判定 | 流程图（分支/汇聚/菱形判定） | 并行来源、汇聚点、判定条件、是/否去向 | 用文本注释替代判定路径 |
| 状态或知识如何回流并持续演化 | 闭环流程图 / 生命周期图 | 回流箭头、触发条件、循环边界 | 单向线性流程图 |
| 多个方法或方案的属性差异 | 对比表；仅在关系需要可视化时用矩阵图 | 统一维度、可比较项、结论性差异 | 复杂节点网络图 |
| 算法中的控制流与数据流 | 算法流程图或伪代码 + 局部流程图 | 输入、核心操作、循环/终止条件 | 总体架构图 |

- 存在“先后执行”“汇聚”“判定”“回退”“丢弃”等动词时，默认选择流程图；判定必须使用菱形节点并绘出每个分支的去向。
- 存在“属于”“包含”“映射”“调用”“导入”等静态关系时，默认选择本体图或关系图；不虚构处理顺序。
- 一张图只服务一种主关系。流程细节与静态本体关系同时重要时，应拆为两张图，而不是在同一画布混搭。

### 2.3 连续处理流程图基线

对于“输入—连续处理—条件判定—输出/回退”的流程，采用以下紧凑版式作为默认基线：

- 主流程沿同一水平基线从左向右排列，输入、处理步骤和主要输出保持等间距；主流程方块优先使用两行文字，最多三行。
- 最终结果需要经过预算、质量或权限判定时，将判定菱形单独放在最后一个处理节点下方；“是/通过”从菱形水平指向右侧输出节点。
- “否/失败/超预算”从菱形垂直向下进入独立的降级或重试节点，再由一条可追踪的回退线返回具体处理节点；禁止直接画一条跨越多个节点的无目标回环线。
- 回退路径必须标注触发条件，且每段线都连接两个明确节点边缘。主链、判定、回退使用不同的线型或低饱和强调色，避免读者混淆执行顺序与反馈路径。
- 主流程和输出节点采用核心文字行高比，降级/重试节点采用普通方块文字行高比；所有节点文字最多三行，图例和触发条件不得压在线上或节点边框上。

### 3. 配色与字体

- 学位论文架构图默认使用白底、黑灰细线和灰色虚线边界。
- 非必要不使用彩色填充；若必须强调，仅使用一种低饱和强调色，并保持论文整体一致。
- 中文默认使用宋体或论文模板指定字体，英文字体与中文风格保持协调。
- 文字优先保证清晰可读。若放不下，依次采用：扩大模块、缩短标签、减少换行、重排画布；不得通过降低文字行高比、过度压缩或贴边解决。
- 重要图谱、核心模型和关键路径应比普通说明文字更醒目，但不能制造文字重叠。

### 4. Visio 生成

使用 Visio COM 自动化时：

- 页面尺寸先确定，再创建图形；生成脚本必须显式设置页面宽高。
- 使用 `CellsU($name).FormulaU` 访问 Visio 单元格，兼容 PowerShell 7 的 COM 参数化属性。
- 使用 Windows PowerShell 5.1 执行 Visio 脚本，避免不同 PowerShell 版本在中文无 BOM 脚本上的解析差异。
- 设置 `$visio.Visible = $false` 和 `$visio.AlertResponse = 7`，避免保存或关闭时弹出隐藏对话框。
- 页面、文档和 Visio 应用对象在结束时按页面 -> 文档 -> 应用的顺序释放；最后执行垃圾回收，确认没有残留 `VISIO.EXE`。
- 不使用无效的页面单元格名称；例如页面对象不设置 `PageLineColor` 和 `PageLineWeight`。
- 文本框和模块框必须分别控制字号、宽度和高度。文字字号放大时同步检查内部换行和相邻元素。

### 5. 论文插入

- Markdown：在正文对应段落后插入相对路径图片，并保留可编辑源文件说明。
- LaTeX：将 PNG 复制到模板 `images` 目录，使用 `figure` 环境、`\centering`、合适的 `width`、`\caption` 和 `\label`。
- DOCX：优先使用行内图片，不使用浮动锚定；图片单独成段居中，图注紧跟图片后并居中。
- 图片内不重复放置论文图题；图题统一由论文编排系统生成。
- 图注名称、编号和正文引用必须一致，不能同时保留“成稿时绘制”等占位说明。

### 6. 验收

生成后必须完成以下检查：

1. 打开或解析 `.vsdx`，确认文件存在且可读取；
2. 导出 PNG 并进行 100% 视觉检查；
3. 检查文字是否裁切、重叠、换行过多或字号不清晰；
4. 检查虚线框标题距离是否统一，元素是否居中，箭头是否指向正确；
5. 检查所有关系连线是否无交叉、无穿越节点、无悬空端点；存在分支或汇聚时，确认每条路径均可沿直线或正交折线独立追踪；
6. 检查论文正文中的图片、图注、编号和引用；
7. DOCX 必须使用文档渲染器导出页面 PNG 后检查；LaTeX 必须编译或至少检查图片路径和 `figure` 结构；
8. 最终目录只保留正式源文件、预览图、生成脚本和本规则，不保留测试图或临时 Visio 文件。
9. 在最终 PNG 检查中，额外确认核心图元占画面主要区域，并按文字行高比逐类验收：核心/主流程至少 3.5%，普通方块/判定至少 3.0%，层级标签至少 2.4%，辅助说明至少 2.0%；发现比例不足、大面积无信息留白或需放大才能看清文字，判定为不通过并重新排版。

## 常见问题与处置

### Visio COM 与 PowerShell

- Windows PowerShell 5.1 读取无 BOM 的 UTF-8 中文脚本时可能出现“字符串未结束”等假解析错误；脚本应写入 UTF-8 BOM，或使用明确的 Windows PowerShell 宿主。
- PowerShell 7 中 `$shape.CellsU.Item($name)` 对某些 COM 参数化属性会失败，应使用 `$shape.CellsU($name)`。
- Visio 保存后若仍持有页面或形状 COM 引用，`Document.Close()` 可能长时间阻塞；必须先释放页面引用，再关闭文档和应用。
- 隐藏 Visio 在 `SaveAs` 或 `Export` 时可能等待对话框；设置 `AlertResponse` 并检查是否残留 `VISIO.EXE`。

### 版式与文字

- 仅放大字号会导致长标签自动换行并与说明文字重叠；应同时缩短核心标签或扩大模块宽度。
- 左侧层级标签宽度不足时，三字标签会被拆成三行；应扩大文本框宽度并控制字号。
- 第一块模块过于靠近虚线框左边界时，模块边线和外框线会视觉重合；保留至少一个箭头或半个模块高度的安全间距。
- 层标题不能按内容临时摆放，应统一相对于各自虚线框顶部的偏移。
- 图内标题会与论文外部图注重复；论文正式插图不在图片内部绘制图题。
- 说明文字必须与模块留出空白，不能把说明文字放到模块底边或箭头线上。
- 流程图中的主链箭头统一保持同一方向和基线；反馈箭头使用独立的回退节点，并在起点附近标注“超预算/失败/否”等触发条件，避免让读者猜测回流目标。
- 画布过高会把本可清晰显示的文字缩得过小，并制造大面积无信息留白；应先按内容确定紧凑画布比例，再放大节点和文字，不能把“安全边距”误当作大面积空白。
- 有明确输入、处理、聚合、判定和输出的内容若画成静态关系图，会掩盖步骤顺序和分支语义；应使用箭头明确的流程图，阈值或条件使用菱形并标记去向。
