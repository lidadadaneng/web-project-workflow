## 三、docx 结构关键知识

- **锚点段落**：章节标题样式名为 `Heading 1` / `u1级标题`（参考文献等）/ `u2级标题` / `u3级标题` / `u正文` / `u表标题` / `u图标题` / `u附录标题` / `u参考文献条目顺序编码制`。**模板无四级标题样式**，md 三级以下小节降为黑体引导段。
- **正文排版**：中文宋体、英文与数字 Times New Roman、小四（12 pt）、两端对齐、首行缩进 2 字符、1.3 倍行距。导入正文时必须显式覆盖锚点段落遗留的直接格式，不能只克隆模板占位段落；验收时普通正文居中段落数必须为 0。
- **摘要内容口径**：中英文摘要只概述研究问题、方法、评估维度和定性结论，不写任务数量、模型总 Token、Recall、通过率、百分比等具体实验数据；全部定量结果集中放在第 6 章。
- **图表标题与正文引用**：图表编号统一使用 `图3-1` / `表3-1` 格式，图（表）与编号之间不留空格，章节号与序号之间使用半角连字符 `-`；正文引用统一写为 `如图3-1所示` / `如表3-1所示`，不写成带空格的 `如图 3-1 所示`。图题段落使用 `u图标题`，表题段落使用 `u表标题`。修改 md 后同步 docx，并在验收时检查标题、正文引用和图表清单三处格式一致。
- **图与图题**：正文图片按原比例缩放，宽度不得超过版心宽度 15 cm；图题使用黑体/Times New Roman 五号（10.5 pt）、加粗、居中，图题位于图下。
- **表题识别**：Markdown 中紧邻表格前、独立成段且以 `表N-M` 开头的行才是表题，导入 Word 时使用 `u表标题`；正文中的“表N-M给出/列出……”保持 `u正文`，不能误设为表题。表题不靠段落索引识别，而由解析器按“表题 + 后续表格”的结构定位。
- **表格排版**：章内表格使用三线表（仅表顶线、表头下横线和表底线），表格整体居中；中文宋体、英文与数字 Times New Roman、五号（10.5 pt）。表头加粗并设置跨页重复，表格行禁止跨页断行；数字列按 Markdown 对齐标记右对齐，其余列按源表对齐。表题使用黑体/Times New Roman 五号、加粗、居中，位于表上。
- **显示公式布局**：显示公式使用同一段落中的“居中制表位 + 右对齐制表位”，公式主体视觉居中，`（N-M）` 编号贴右边界；不要用连续空格或普通制表符模拟。转换后验收应检查段落 `w:tabs` 同时包含 `center` 与 `right` 两个制表位，且公式段落无首行缩进。
- **算法/伪代码块**：Markdown fenced code（特别是“算法 N-M”后的伪代码）导入 Word 时必须保持为一个完整代码块，不得按行拆成普通正文。代码块使用 `Plain Text` 段落、Consolas 等宽字体、约 9 pt、单倍行距、左右缩进和浅灰底纹；代码内部换行保留，算法标题与代码块分开。验收时检查代码块段落数量、`Plain Text` 样式、等宽字体和底纹。
- **标题自动编号**：样式自带编号，导入 md 时必须剥掉手写编号（`第X章`、`1.1 `）。
- **目录是 Word 域**：脚本保留目录并写入 `w:updateFields=true`，Word 打开文档时会请求自动更新全部域；如未自动刷新，使用 Ctrl+A -> F9 作为兜底。
- **分节符/分页符藏在段落里**：任何批量删除前必须检查段落 XML 是否含 `w:sectPr` / `type="page"` / `fldChar`（目录域），含则跳过该段（保留空壳），否则页面结构会被破坏。
- **公式**：当前含 14 个显示公式和 14 个含行内公式的段落，均转为 OMML 原生公式。显示公式编号覆盖式 (2-1)~(2-2)、式 (3-1)~(3-5)、式 (4-1)~(4-2)、式 (5-1)~(5-2) 和式 (6-1)~(6-3)；md 里的 `$$公式$$ \tag{3-1}` 转换时会剥离 `\tag` 并在公式后补「（3-1）」文本 run。
- **引用**：正文 [n] 已转上标（vertAlign=superscript），转换时排除数值含 0 的区间（如 [0,1] 是置信度区间不是引用）。
- **参考文献序号**：`u参考文献条目顺序编码制` 样式自带 `[1]`、`[2]`……自动编号，`unify_refs.py` 生成的条目正文不得再手写 `[n]` 前缀；验收时 68 个参考文献段落的 `Paragraph.text` 均不得以 `[` 加数字开头。
- **盲审约定**（见记忆 thesis-positioning-plan）：封面学号/作者/导师留空；不写工具排行榜；研究定位三句话。

## 六、排坑经验（问题 -> 原因 -> 解法）

1. **控制台中文乱码** -> Windows 默认 GBK -> 一律 `-X utf8`；长输出写临时文件再 Read，不硬看 stdout。
2. **`python` 起不来/语法怪异** -> 解析到 Python 2.7 -> 用 Python311 完整路径。
3. **find_para 按索引找不到段落** -> 段索引会因表格偏移（body 块索引 ≠ 段落索引）-> 一律按**文本内容+样式名**定位。
4. **文本匹配失败（破折号/撇号）** -> 模板用全角 em dash `--`（U+2014x2）而非 ASCII `--`；`Baker's` 的撇号是非 ASCII 变体 -> 用 `repr()`/`[hex(ord(c))]` 查真实字符，匹配用包含式（`'Mechanistic' in p.text`），不确定就先 hex dump。
5. **批量删段后页面结构崩** -> 分节符（sectPr）和分页符寄生在被删段落里 -> 删前检查 `el.xml` 含 `w:sectPr`/`type="page"`/`fldChar` 则跳过。
6. **parse_xml 报 `xmlParseEntityRef: no name`** -> 文献文本含未转义 `&` -> 构造 XML 前做 `& < >` 转义。
7. **删除范围失控（一次误删 352 段）** -> 删除循环没设终点 -> **删除操作必须设停止条件**（下一个 Heading 1 或保留标记）；且**脚本只在全部步骤成功后才 save**--本次两次中途崩溃都因未到 save 而未损坏磁盘文件，这是保命设计，写新脚本时保持。
8. **标题出现双重编号（1.1 1.1 xxx）** -> 样式已自动编号而 md 带手写编号 -> 导入时 strip 前缀（`第\s*\d+\s*章`、`^\d+(\.\d+)*\s+`）。
9. **`\item [1]` 被当成自定义标签**（LaTeX）-> item 文本以 `[` 开头时补 `{}`。
10. **公式转换失败** -> latex2mathml 不支持 `\tag` -> 剥离 `\tag{x}` 后转公式；编号通过居中/右对齐制表位定位，不用连续空格模拟。
11. **引用上标误伤** -> `[0,1]` 这类区间不是引用 -> 上标化前校验括号内所有数字在 1-`len(REFS)`。
12. **pip 装包 403/超时** -> 直连与清华镜像均不可用 -> 阿里云镜像。
13. **`d.save` 报 PermissionError [Errno 13]** -> docx 正被 Word 打开（目录可见 `~$xxx.docx` 锁文件）-> 请用户关闭文档后重跑；脚本在 save 前崩溃不会损坏磁盘文件（保命设计）。`unify_refs.py` 的引用号上限已与 `REFS` 长度动态同步。
14. **正文整篇居中** -> 导入脚本克隆了带居中直接格式的模板占位段落 -> 创建普通正文后显式设置两端对齐、首行缩进和 1.3 倍行距，并统一重设中英文字体；验收时按正文样式统计居中段落，结果必须为 0。
15. **参考文献序号显示两遍** -> 参考文献样式已经自动编号，脚本又在正文中写入了 `[n]` -> 参考文献段落只写题录正文，序号完全交给 `u参考文献条目顺序编码制` 样式生成。

## 七、Word 端手工步骤（脚本做不了，提醒用户）
